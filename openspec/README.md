# 給 IT 工程師的快速導讀

## 這是什麼

盤點班表調移系統的前端。**純靜態 SPA，無資料庫、無寫入需求。**

排班人員匯入 Excel 班表 → 拖曳調整人員與門市 → 匯出 Excel。系統會自動比對資料，提示「某人今天被排太多間」「已休假卻被排班」「同一間店排了兩次」。

---

## 你需要做的事

**只有兩支唯讀 GET API。** 其餘功能前端已完成，不需後端參與。

| API | 用途 |
|---|---|
| `GET /api/staff/roster?dept=北一課` | 人員通訊錄 |
| `GET /api/staff/leave?dept=北一課&yearMonth=202608` | 人員休假日期 |

完整欄位規格與 Request／Response 範例見 **`api-interface.json`**。

### 程式進入點

所有待串接處集中在 **`src/services/staffApi.js`**，以 `// TODO: IT 工程師請在此串接後端 API` 標註。呼叫時機在 `src/App.jsx` 的 `useEffect`（班表匯入後自動觸發），一般情況不需修改。

### API 位址設定

於專案根目錄建立 `.env`：

```
VITE_API_BASE_URL=https://your-api-host/api
```

未設定時預設走同網域 `/api`。

## 四個容易踩到的重點

### 1.「班表代號」是人員辨識的基礎

班表的「預定盤點者」欄位存的是單字代號串（例如「于筱董」代表三個人），前端會逐字拆解後比對通訊錄的「班表代號」欄位。此欄位在同一課別內必須唯一。

### 2. 工號對照**不需要**你提供

班表的「盤點1～8」欄位依序就是「預定盤點者」每個代號的工號，前端匯入時會自動建立對照表（實測 390 列建出 28 個代號、零衝突）。所以通訊錄 API 的價值在於**姓名、職稱、完整名單**，而非工號。

### 3. 休假日期請回傳完整 yyyyMMdd

原 Excel 是「8/19、8/20、8/21」且沒有年份。請由後端展開成 `["20260819","20260820","20260821"]`，前端不再做字串拆解。

### 4. 兩支 API 的「姓名」必須完全一致

前端以「姓名」關聯休假紀錄與人員資料。若有全形半形或空白差異會對不上。

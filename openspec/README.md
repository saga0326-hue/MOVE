## API 規格

完整欄位定義與 Request／Response 範例見 **`api-interface.json`**（該檔為權威）。

| API | 用途 |
|---|---|
| `GET /api/staff/roster?dept=北一課` | 人員通訊錄 |
| `GET /api/staff/leave?dept=北一課&yearMonth=202608` | 人員休假日期 |

前端會依匯入班表推導出的課別與年月自動帶入查詢參數，可重複帶多個值。

## 四個容易踩到的重點

### 1. 工號對照**不需要**你提供

班表的「盤點1～8」欄位依序就是「預定盤點者」每個代號的工號，前端匯入時會自動建立對照表（實測 390 列建出 28 個代號、零衝突）。

所以通訊錄 API 的價值在於：

- **姓名與職稱** — 出勤列的滑鼠提示
- **完整名單** — 才知道誰今天沒被排到（白色圓圈）
- **姓名↔代號橋接** — 休假資料以姓名為鍵，需靠通訊錄對應回代號

### 2.「班表代號」必須在同課別內唯一

班表的「預定盤點者」存的是單字代號串（例如「于筱董」代表三個人），前端會逐字拆解後比對通訊錄的「班表代號」欄位。若同課別內重複，統計會失準。

### 3. 休假日期請回傳完整 yyyyMMdd

原 Excel 是「8/19、8/20、8/21」且沒有年份。請由後端展開成：

```json
["20260819", "20260820", "20260821"]
```

前端不再做字串拆解。

### 4. 兩支 API 的「姓名」必須完全一致

前端以「姓名」關聯休假紀錄與人員資料。全形半形或前後空白的差異會導致對不上。

## 需要你確認的事項

1. **驗證方式** — 目前為 `credentials: 'same-origin'`。若採 Token／SSO，需調整 `src/services/staffApi.js`
2. **「班表代號」欄位** — 請確認人事系統中確實有此欄位
3. **課別參數格式** — 目前直接帶中文課別名稱（如 `北一課`），若後端需要代號請告知

---

## 錯誤處理行為

非 2xx 或連線失敗時，前端會：

- 顯示「人員資料 API 尚未連線，出勤統計改以班表內容顯示」
- 退回「僅統計班表內出現的代號」模式
- **不中斷**班表匯入、拖曳、編輯與匯出

因此 API 未完成期間系統仍可正常使用，可先跑起來看畫面再決定實作方式。

## 你要做的事

**串接三支唯讀 GET API**，集中在兩個檔案，皆有 `// TODO` 標註。

| 檔案 | API | 用途 |
|---|---|---|
| `src/services/staffApi.js` | `GET /staff/roster` | 人員通訊錄 |
| | `GET /staff/leave` | 人員休假 |
| `src/services/storeApi.js` | `GET /stores` | 店鋪檔 |

完整欄位定義與 Request／Response 範例見 **`api-interface.json`**（該檔為權威）。

呼叫時機在 `src/App.jsx` 的 `useEffect`，班表匯入後依課別與年月自動觸發，一般不需修改。

API 位址於 `.env` 設定：

```
VITE_API_BASE_URL=https://your-api-host/api
```

## 五個容易踩到的重點

### 1. 工號對照**不需要**你提供

班表的「盤點1～8」欄位依序就是「預定盤點者」每個代號的工號，前端匯入時會自動建立對照表（實測 390 列建出 28 個代號、零衝突）。

所以通訊錄 API 的價值在於：

- **姓名與職稱** — 出勤列的滑鼠提示
- **完整名單** — 才知道誰今天沒被排到（無色圓圈）
- **姓名↔代號橋接** — 休假資料以姓名為鍵，需靠通訊錄對應回代號

### 2. 門市主檔同樣可自推導，店鋪檔是用來「補洞」的

班表中出現過的門市，前端已能推導出店名、型態、課別、課別代號、營業課別、前次盤點（實測 393 間門市六個欄位皆 1 對 1）。

`GET /stores` 是為了補齊**不在班表中**的門市：

- 新開店
- 其他月份的店，本月因閉店／轉手／解約而臨時排入
- 跨課別支援的門市

### 3. 店名必須唯一

前端提供「輸入店名反查店號」的功能（使用者常記得店名但忘記店號）。目前 393 間門市店名皆唯一；若店鋪檔中出現同名不同店號，前端只會取第一筆。

同理，「班表代號」在同一課別內也必須唯一，否則出勤統計會失準。

### 4. 休假日期請回傳完整 yyyyMMdd

原 Excel 是「8/19、8/20、8/21」且沒有年份。請由後端展開成：

```json
["20260819", "20260820", "20260821"]
```

前端不再做字串拆解。

### 5. 兩支人員 API 的「姓名」必須完全一致

前端以「姓名」關聯休假紀錄與人員資料。全形半形或前後空白的差異會導致對不上。

## 需要你確認的事項

1. **驗證方式** — 目前為 `credentials: 'same-origin'`。若採 Token／SSO，需調整兩個 service 檔案
2. **「班表代號」欄位** — 請確認人事系統中確實有此欄位
3. **課別參數格式** — 目前直接帶中文課別名稱（如 `北一課`），若後端需要代號請告知
4. **店鋪檔資料量** — 若全省店庫筆數過大需分頁或增量同步，請告知以便調整前端

---

## 錯誤處理行為

任一 API 非 2xx 或連線失敗時，前端會：

- 顯示「人員資料 API 尚未連線，出勤統計改以班表內容顯示」
- 降級為僅統計班表內出現的代號
- **不中斷**班表匯入、拖曳、就地編輯、匯出、店暫存區與重複盤點警告

因此 API 未完成期間系統仍可正常使用，建議先跑起來看畫面再決定實作方式。

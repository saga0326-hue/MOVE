| 項目 | 內容 |

---

## 1. 系統目的

排班人員每月需依門市盤點需求編排班表。原作業方式為直接編輯 Excel，缺點是：

- 調動人員或門市時需手動剪貼多個儲存格，容易錯位
- 難以一眼看出某人當天被排了幾間店
- 無法察覺「已排休假的人被排入班表」

本系統將 Excel 班表轉為可視化卡片，支援拖曳調移，並自動比對人員與休假資料提出警示。

---

## 2. 使用流程

```
使用者匯入班表 Excel
        │
        ▼
前端解析 → 依日期分群（每日 15 組 × 上下午）
        │
        ├─→ 自動呼叫 API 取得該課別人員通訊錄與休假資料
        │
        ▼
畫面呈現：日期切換 / 當日出勤列 / 休假衝突警告 / 15 組班表卡片 / 店暫存區
        │
        ▼
使用者拖曳調移（門市↔門市、人員↔人員、暫存區↔槽位）
        │
        ▼
匯出 Excel（欄位與列序完全還原成原始格式）
```

## 3. 功能規格

### 3.1 班表匯入

- 支援點擊選檔或**拖曳檔案**到虛線區塊
- **標題列位置動態偵測**：掃描前 20 列，找到同時含「午別」「日期」「店號」的列即視為標題列，不假設固定列數
- **欄位動態辨識**：除已知欄位外，未預期的欄位（如「盤點1」～「盤點8」）一律原樣保留，匯出時不遺失
- 依「日期」分群，每個日期固定 30 列 ＝ 15 組 ×（午別 1 上午／午別 2 下午）
- 資料不足 30 列自動補空列，超過則截斷，並於 console 提出警告
- **組內配對規則**：依原始檔案位置成對切分（第 1、2 列為第 1 組…），組內再依「午別」欄位值決定上下午，**絕不重新排序**

已驗證：以實際班表（31 天、930 列、21 欄）測試匯入→匯出，除去除儲存格前後多餘空白外，逐格比對完全一致。

### 3.2 拖曳調移

| 拖曳來源 | 拖曳目標 | 行為 |
|---|---|---|
| 門市卡片 | 另一槽位的門市卡片 | 兩槽位的門市欄位互換 |
| 人員卡片 | 另一槽位的人員卡片 | 兩槽位的人員欄位互換 |
| 店暫存區 | 槽位門市卡片 | 指派該店，並從暫存區移除 |
| 槽位門市卡片 | 店暫存區 | 門市退回暫存區，該槽位清空 |

- 「門市欄位」與「人員欄位」由匯入時動態決定：
  - 結構性欄位（序、午別、日期）→ 固定於位置，不隨拖曳移動
  - 人員欄位（預定盤點者、備註）→ 屬人員卡片
  - 其餘全部（店號、店名、型態、前次盤點、課別、人力、課別代號、營業課別、盤點1～8）→ 屬門市卡片
- 15 組 × 上下午的框架在任何操作下都不會被打亂

### 3.3 當日出勤列

顯示該課別全體人員的單字代號，依當日被排班次數上色：

| 顏色 | 條件 | 意義 |
|---|---|---|
| 無色 | 0 次 | 今日未排班 |
| 淡藍 | 有休假且 0 次 | 正常休假 |
| 黃 | 1 次 | 帶 1 間店 |
| 綠 | 2 次 | 帶 2 間店（常態） |
| 紅 | ≥3 次，**或** 有休假卻仍被排班 | 需留意（庫存少時 3 間屬合理，僅作提示） |

**計算規則（重要）**

- 僅統計**店號有填**的槽位。班表中店號空白的列常被用來記錄業務備註（如「效期 青+2PT」「秀皓 歐都納」），若一併統計會產生大量雜訊代號
- 「預定盤點者」欄位**逐字拆解**，每個字視為一位人員代號。例如「于筱董」＝ 于、筱、董 三人各計 1 次
- 課別範圍取自**整份班表**（掃描所有日期），而非當前日期。因週日等無排班日抓不到課別，會導致列出全部課別人員
- 代號在通訊錄中查無者（例如新人尚未建檔）仍照常顯示並計次，以虛線外框標示，滑鼠提示「通訊錄尚未建檔」

### 3.4 休假衝突警告

當某人當日有休假紀錄、且其代號出現在班表中，於班表上方顯示琥珀色橫幅，列出姓名、代號、假別、以及被排入的組別與時段。

需同時取得通訊錄（姓名↔代號對照）與休假資料才會啟用；任一缺少時橫幅不顯示。

### 3.5 店暫存區

側邊面板，可手動新增門市或匯入「店庫異動」Excel（以店號比對：既有則更新、新增則附加）。可與班表槽位雙向拖曳。

### 3.6 班表匯出

依匯入時記錄的欄位順序與原始標題文字還原，每日 30 列。若原檔含「序」欄，匯出時依槽位位置重新編號為 01～30。

## 4. 資料來源對照表

| 資料項目 | 來源 | 交接後方式 |
|---|---|---|
| 班表（午別／日期／店號／店名／型態／前次盤點／預定盤點者／備註／課別／人力／課別代號／營業課別／盤點1-8） | 使用者本機 Excel | **維持不變**，前端解析 |
| 店庫異動（店號／店名／型態／課別…） | 使用者本機 Excel | **維持不變**，前端解析 |
| 人員通訊錄（課別／工號／姓名／職稱／班表代號） | 原為 Excel 匯入 | **改為 API**：`GET /staff/roster` |
| 人員休假（課別／姓名／休假日期／假別） | 原為 Excel 匯入 | **改為 API**：`GET /staff/leave` |

## 5. 需 IT 協助的介接點

程式中所有待串接處皆以 `// TODO: IT 工程師請在此串接後端 API` 標註，集中於單一檔案：

**`src/services/staffApi.js`**

```js
export async function fetchRoster(departments) { ... }   // GET /staff/roster
export async function fetchLeave(departments, yearMonths) { ... }  // GET /staff/leave
```

呼叫時機：`src/App.jsx` 的 `useEffect`，於班表匯入後、取得課別與年月時自動觸發。

### 需確認事項

1. **驗證方式**：目前為 `credentials: 'same-origin'`。若採 Token/SSO，請告知以便調整
2. **API 位址**：透過環境變數 `VITE_API_BASE_URL` 設定，預設 `/api`
3. **「班表代號」欄位**：此欄位是整套統計的關鍵。需確認人事系統中確實有此欄位，且同一課別內唯一
4. **姓名一致性**：兩支 API 的「姓名」需完全一致，前端以此關聯休假與人員

## 7. 非功能性需求

- **無後端相依的降級行為**：API 無法連線時顯示提示，出勤列退回「僅統計班表內出現的代號」模式，班表匯入／拖曳／匯出完全不受影響
- **響應式版面**：欄數依螢幕寬度自動調整（2／3／4／5 欄），已於 1920、1366、1024、768 四種解析度驗證無橫向捲軸
- **資料不落地**：所有 Excel 於瀏覽器記憶體處理，不上傳；人員資料僅存在於當次瀏覽階段，重新整理即清空

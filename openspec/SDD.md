| 項目 | 內容 |
|---|---|
| 系統名稱 | 盤點班表調移系統 |
| 系統代號 | INV-SHIFT |
| 版本 | 2.0.0 |
| 前端技術 | React 19 + Vite 8 + Tailwind CSS 4 |
| 拖曳套件 | @hello-pangea/dnd 18 |
| Excel 處理 | SheetJS (xlsx) |
| 部署型態 | 純靜態 SPA，亦可打包為單一 HTML 檔直接開啟 |
| 後端需求 | 3 支唯讀 GET API（見 `api-interface.json`），未串接亦可運作 |
| 資料庫 | 無。本系統不寫入任何資料 |

> 資料模型由「每日 15 組固定格狀」改為「依檔案順序排列的扁平列」。
> 舊版班表匯入檔仍相容。

---

## 1. 系統目的

排班人員每月需依門市狀況調整盤點班表。原作業方式為直接編輯 Excel，缺點是：

- 調動人員或門市時需手動剪貼多個儲存格，容易錯位
- 同一人的工號分散於「盤點1～8」欄，人員異動時容易忘記同步
- 難以看出某人當天被排了幾間店
- 無法察覺「已排休假的人被排入班表」或「同月重複盤點」

本系統將班表轉為可視化卡片，支援拖曳調移與就地編輯，並自動比對資料提出警示。
匯出檔案與匯入來源格式完全一致，可直接沿用既有流程。

---

## 2. 使用流程

```
匯入盤點行事曆勤務報表
        │
        ├─ 偵測格式、定位標題列、解析欄位
        ├─ 依檔案順序建立扁平列，固定分組（_gid）
        ├─ 補齊各組缺少的午別（空白槽位）
        ├─ 推導「人員代號 → 工號」對照表
        ├─ 推導「店號 → 門市資料」主檔
        └─ 依課別與年月呼叫 API 取得通訊錄／休假／店鋪檔
        │
        ▼
畫面：固定資訊區（日期／警告／出勤列）＋ 組別卡片 ＋ 店暫存區
        │
        ├─ 拖曳調移、雙擊就地編輯、彈窗詳細編輯
        ├─ 批次勾選門市移至暫存區
        └─ 新增／刪除組別
        │
        ▼
匯出 Excel（格式完全還原）
```

## 3. 資料模型

### 3.1 核心結構

```js
scheduleData = {
  format: 'report' | 'grid',
  dates: ['20260803', ...],          // 已排序
  byDate: { '20260803': [row, ...] }, // 依檔案原始順序的扁平列
  columns: [{ index, key, header }],  // 匯入時的欄位定義
  storeKeys: [...], staffKeys: [...],
  preamble: [[...], ...],             // 標題列之前的報表標頭
  sheetName, dateStyle, shiftStyle,
}
```

每一列（row）帶有兩個系統欄位：

| 欄位 | 用途 |
|---|---|
| `_rid` | 該列的穩定識別碼，拖曳與編輯皆以此定位 |
| `_gid` | 所屬組別，**匯入時決定後即固定** |
| `_added` | 標記系統補出的空白槽位（非來源資料） |

> **為何採扁平列**：報表格式每日筆數不固定（實測 2～23 筆），
> 且同一組可能有多列（如出差一天跑 3 間店），原本「15 組 × 上下午」
> 的固定格狀無法表達。改為扁平列後兩種格式可共用同一套邏輯。

### 3.2 欄位歸屬

拖曳時哪些欄位跟著走，取決於此分類：

| 分類 | 欄位 | 行為 |
|---|---|---|
| **結構性** | 序、午別、日期 | 固定於位置，不隨拖曳移動 |
| **人員** | 預定盤點者、人力、盤點1～8 | 隨人員卡片移動 |
| **門市** | 店號、店名、型態、前次盤點、**備註**、課別、課別代號、營業課別，以及其他未預期欄位 | 隨門市卡片移動 |

實作於 `utils/scheduleParser.js` 的 `isStaffKey()`。

**兩項曾經歸類錯誤，已修正並驗證：**

- **「人力」與「盤點1～8」屬人員**。盤點N 依序對應「預定盤點者」各代號的工號。
  以 390 列實際資料驗證：盤點N 數量與代號字數 0 筆不符、人力與人數 0 筆不符。
  原歸為門市，導致互換人員時工號留在原地、匯出後工號對錯人。
- **「備註」屬門市**。其內容（如「四課勿動」「北二勿動」）註記的是門市歸屬與限制。
  原歸為人員，導致互換人員時備註跟著人跑、與門市脫勾。

## 4. 匯入格式

系統自動偵測，匯出時還原成相同格式。

| 特徵 | report（現行來源） | grid（舊版，相容） |
|---|---|---|
| 檔名 | `INV_7_5盤點行事曆_勤務行事曆報表_*.xlsx` | `班表匯入_北一*.xlsx` |
| 標題列 | 第 7 列（前 6 列為報表標頭） | 第 1 列 |
| 午別 | `上` / `下` | `1` / `2` |
| 日期 | `2026/08/03` | `20260803` |
| 每日筆數 | 不固定（實測 2～23） | 固定 30 列 |
| 序 | 全域流水號 | 每日 01～30 |

**判定條件**：每個日期皆為 30 列且午別為數字者視為 grid，其餘為 report。

### 4.1 標題列偵測

掃描前 30 列，找到同時含「午別」「日期」「店號」的列即為標題列。
標題列之前的內容存入 `preamble`，匯出時原樣還原（報表的盤點月份、部別、課別、店數等）。

### 4.2 欄位辨識

以關鍵字比對分類（`classifyHeader`），未預期的欄位沿用原始標題文字作為 key，
匯出時原樣寫回，因此來源報表新增欄位不會遺失。

### 4.3 正規化

| 項目 | 處理 |
|---|---|
| 午別 | `上`→1、`下`→2；記錄原始寫法供還原 |
| 日期 | 一律轉為 `yyyymmdd`；記錄原始樣式（slash／dash／compact） |
| 補零 | 店號 6 碼、前次盤點 8 碼 |
| 空白 | 儲存格前後空白與換行一律清除 |

> **型態不補零**。其值為 FC／RC／轉／解 等代碼，偶有「0」之類的輸入殘留，
> 補成「0000」會改動來源資料。

## 5. 分組規則

**分組於匯入時決定並寫入 `_gid`，之後不再重算。**

### 5.1 為何不以「序」排序

報表的「序」是全域流水號，與分組順序無關。以 2026/08 實際資料驗證：

| 排序方式 | 同組是否相鄰 |
|---|---|
| **檔案原始順序** | 215 組全部連續，**0 組被打散** |
| 依「序」排序 | 完全打散（君雅→芝欣→君雅→嫺綉→董憶…） |

因此一律依檔案原始順序，序僅作為資料欄位保留。

### 5.2 分組演算法

- **report**：依檔案順序，相鄰且「預定盤點者」首字（帶隊者）相同者為一組
- **grid**：每 2 列為一組（舊格式依位置成對）

實測結果：平均每日 8.0 組；同日首字不會對應到兩個不同組；
僅 1 組超過 2 列（08/28 澎湖出差，同組一天跑 3 間店，屬合理情況）。

### 5.3 為何固定不重算

使用者調動人員後首字可能改變，若即時重算會導致卡片重新分組並跳位置。
固定後已驗證三種情境（首字改變、跨組互換人員、清空人員）組數與位置皆不變。

### 5.4 補齊午別

來源報表只列出實際有安排的工作，常見某組只有上午或只有下午。
匯入時為每組補上缺少的午別空白槽位（`_added: true`），組內固定上午在前，
供使用者將其他日期的門市調移進來。這些列若始終未填入內容，匯出時會被略過。

## 6. 自動推導的對照表

兩份對照表皆由匯入的班表自行推導，**不需外部 API**。

> **重要**：兩者於匯入時建立一次即固定，不隨編輯重算。
> 若依當前資料重算，門市被移到暫存區後其列的店號被清空，該店即從主檔消失，
> 導致重新輸入店號時查不到（v1.x 曾有此缺陷，已修正）。

### 6.1 人員代號 → 工號

每列的「預定盤點者」是代號串（如「董憶瑄」），「盤點1～8」依序是對應工號。
掃描整份班表即可還原（`staffUtils.buildCodeToIdMap`）。

- 僅採用店號有填的列，避免備註列的雜訊文字混入
- 代號數與工號數不符的列略過
- 同一代號對應多個工號時取出現次數最多者

實測：390 列建出 28 個代號、**零衝突**；以此重算全部資料，與原檔完全一致。

**用途**：使用者修改「預定盤點者」後，自動重算「人力」與「盤點1～8」。

### 6.2 店號 → 門市資料

同一店號在班表各處的屬性一致，可建立門市主檔（`storeMaster.buildStoreMaster`），
涵蓋店名、型態、課別、課別代號、營業課別、前次盤點。

實測：393 間門市六個欄位皆 1 對 1、**零衝突**；重填全部 2340 格與原檔完全一致。
（營業課別本身會重複，393 間店僅用 17 種，但店號→營業課別方向唯一）

另建立**店名反查索引**（`buildNameIndex`）。已驗證 393 間門市店名皆唯一，
供使用者記不得店號時以店名反查。

**主檔合併順序**：匯入班表 → 店鋪檔 API → 目前暫存區中的門市。

## 7. 功能規格

### 7.1 匯入

支援點選檔案或**拖曳檔案**至虛線區塊。

### 7.2 拖曳調移

| 來源 | 目標 | 行為 |
|---|---|---|
| 門市卡片 | 另一列的門市卡片 | 門市欄位互換 |
| 人員卡片 | 另一列的人員卡片 | 人員欄位互換（含人力與工號） |
| 店暫存區 | 列的門市卡片 | 指派；原門市退回暫存區**原索引位置**，不覆蓋遺失 |
| 列的門市卡片 | 店暫存區 | 門市退回暫存區，該列清空 |

拖曳識別碼為 `type|_rid`（`utils/dnd.js`），不再依賴組別與午別座標。

### 7.3 就地編輯（雙擊）

- **人員**：雙擊即切換為輸入框，Enter 儲存、Esc 取消、失焦亦儲存。
  輸入過程即時顯示人數與各代號，查無工號者標紅。儲存時同步人力與盤點1～8。
- **門市**：雙擊展開店號與店名兩欄，**雙向連動**——任一欄對得上即帶入其餘欄位。
  對不上時標紅「查無此門市，連動欄位不會更新」，不會靜默沿用上一家的資料。
  備註沿用原值不被連動覆蓋。留空即清除該槽位門市。

> 輸入框位於可拖曳卡片內，需攔截 mousedown／click，否則會被拖曳套件視為拖曳起手。

### 7.4 彈窗編輯

以 `createPortal` 掛載至 `document.body`，避免被側邊面板與固定區塊的
sticky／overflow 裁切。最高 90vh，內容過長時彈窗內自行捲動。

### 7.5 店暫存區

- **新增店**：店號或店名任一輸入即自動帶入其餘欄位；可設定指定日期
- **匯入店庫異動**：必填店號；日期欄轉為指定日期限制
- 面板隨捲軸固定，位置依上方固定區塊的實際高度動態計算（ResizeObserver）

**日期標記語意**（兩者不同）：

| 標記 | 來源 | 是否限制 |
|---|---|---|
| `限 MM/DD` | 店庫異動匯入、新增店時指定 | **是**，拖到別天會被擋下 |
| `原 MM/DD` | 從班表移出時記錄 | 否，可放到任何日期 |
| `已排 MM/DD` | 該店已排在班表其他位置 | 否，僅提醒 |

**日期欄正規化**（`normalizeDate`）：支援完整日期與省略年份的寫法，
後者對照班表日期補年份。故建議先匯入班表再匯入店庫異動。

### 7.6 批次移動與組別管理

- 卡片可勾選，浮動操作列一次將多間門市移至暫存區（人員保留於原列）
- 「新增組別」建立含上午與下午的空白組
- 空白組別可單獨刪除，達 2 個以上時提供一次清除
- 判定條件為門市與人員皆空，故「移走門市但人員仍在」不會被誤判

### 7.7 當日出勤列

| 顏色 | 條件 |
|---|---|
| 無色 | 0 次（今日未排班） |
| 淡藍 | 有休假且 0 次 |
| 黃 | 1 次 |
| 綠 | 2 次 |
| 紅 | ≥3 次，或有休假卻仍被排班 |

紅色為提示而非錯誤——門市庫存較少時一人帶 3 間屬合理情況。

**計算規則**：僅統計店號有填的列；「預定盤點者」逐字拆解；
課別範圍取自整份班表（週日等無排班日抓不到課別）。
代號在通訊錄中查無者仍照常顯示並計次，以虛線外框標示。

### 7.8 自動警告

- **同月重複盤點**：掃描整份班表，橘色橫幅列出，日期標籤可點擊跳轉。
  閉店／轉手／解約／續約等異動可能需要同月再盤一次，故**僅警告不阻擋**。
- **休假衝突**：當日有休假卻仍被排班者，琥珀色橫幅列出姓名、假別與所在位置。
  需同時取得通訊錄與休假資料才啟用。

兩個橫幅皆可收合。上方固定區最高佔畫面 45%，超出時該區自行捲動。

### 7.9 匯出

| 項目 | 處理 |
|---|---|
| 報表標頭 | 前 6 列原樣還原 |
| 欄位順序 | 完全比照匯入 |
| 列順序 | 依畫面順序（即匯入的檔案順序） |
| **序** | **保留原值不重新編號**（可能是來源系統的識別依據） |
| **人力** | **依預定盤點者人數重算**，避免調整後殘留舊值 |
| 空白列 | 門市與人員皆空者不寫入 |
| 人員仍在者 | 即使門市已移走仍照常輸出 |

**驗證**：397 筆報表匯入後直接匯出，逐格比對 **0 差異**（含標頭、日期格式、午別寫法）。
新增 10 組空白後匯出仍為 397 筆。

### 7.10 版面

| 螢幕寬度 | 欄數 |
|---|---|
| < 640px | 1 |
| ≥ 640px | 2 |
| ≥ 1024px | 3 |
| ≥ 1280px | 4 |
| ≥ 1536px | 5 |

上方資訊區與店暫存區皆隨捲軸固定。日期切換器以顏色標示週末（週日紅、週六綠）。

## 8. 需 IT 協助的介接點

所有待串接處皆以 `// TODO: IT 工程師請在此串接後端 API` 標註，集中於兩個檔案：

| 檔案 | API | 用途 |
|---|---|---|
| `src/services/staffApi.js` | `GET /staff/roster` | 人員通訊錄 |
| | `GET /staff/leave` | 人員休假 |
| `src/services/storeApi.js` | `GET /stores` | 店鋪檔 |

呼叫時機於 `src/App.jsx` 的 `useEffect`，班表匯入後依課別與年月自動觸發。

### 各 API 的價值

- **通訊錄**：顯示姓名與職稱、列出今日未排班者、作為休假資料（以姓名為鍵）與代號的橋接。
  **工號對照不需此 API 提供**，前端已可自班表推導。
- **休假**：休假標示與衝突警告。
- **店鋪檔**：補齊不在班表中的門市——新開店、其他月份因閉轉解臨時排入者、跨課別支援門市。

### 需確認事項

1. **驗證方式** — 目前為 `credentials: 'same-origin'`，若採 Token／SSO 需調整
2. **API 位址** — 環境變數 `VITE_API_BASE_URL`，預設 `/api`
3. **「班表代號」欄位** — 需確認人事系統中確有此欄位，且同課別內唯一
4. **姓名一致性** — 通訊錄與休假的「姓名」需完全一致，前端以此關聯
5. **課別參數格式** — 目前帶中文課別名稱（如 `北一課`），若後端需代號請告知

### 降級行為

任一 API 失敗時顯示提示並降級，**班表匯入、拖曳、編輯、匯出、店暫存區、
重複盤點警告皆不受影響**。僅姓名職稱顯示、未排班者列示、休假相關功能需待串接。

## 10. 非功能性需求

- **資料不落地**：所有 Excel 於瀏覽器記憶體處理，不上傳；未使用 localStorage、
  sessionStorage、indexedDB 或 Cookie，重新整理即清空
- **無寫入需求**：系統不回寫任何資料，對外僅三支唯讀查詢
- **免安裝發佈**：可打包為單一 HTML 檔（`npm run build:standalone`），
  JS 與 CSS 全部內嵌，點兩下即可開啟

> 一般建置產物無法以 `file://` 直接開啟——Chrome 會以 CORS 政策擋下外部 ES module。
> 單檔版本將所有資源內嵌以避開此限制。

## 12. 目前限制

| 限制 | 說明 |
|---|---|
| 重新整理清空 | 資料在記憶體，重整需重新匯入（亦即個資不會留存） |
| 不在班表中的門市 | 新開店、他月閉轉解等門市無法自動帶入，需自行填寫或待店鋪檔 API 串接 |
| 無登入與權限 | 單機工具，權限實務上由檔案發送對象控管 |
| 無多人協作 | 各自獨立作業，需以匯出的 Excel 交換 |

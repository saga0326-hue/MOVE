## 1. 系統目的

排班人員每月需依門市盤點需求編排班表。原作業方式為直接編輯 Excel，缺點是：

- 調動人員或門市時需手動剪貼多個儲存格，容易錯位
- 同一人的工號分散在「盤點1～8」欄，人員異動時容易忘記同步
- 難以一眼看出某人當天被排了幾間店
- 無法察覺「已排休假的人被排入班表」或「同一間店被排兩次」

本系統將 Excel 班表轉為可視化卡片，支援拖曳調移，並自動比對資料提出警示。

---

## 2. 使用流程

```
使用者匯入班表 Excel
        │
        ├─→ 動態偵測標題列與欄位，依日期分群（每日 15 組 × 上下午）
        ├─→ 自建「人員代號 → 工號」對照表（來源即班表本身）
        └─→ 依課別與年月自動呼叫 API 取得人員通訊錄與休假資料
        │
        ▼
畫面：日期切換 / 重複警告 / 休假警告 / 出勤列 / 15 組班表卡片 / 店暫存區
        │
        ▼
使用者拖曳調移、編輯槽位、從暫存區指派門市
        │
        ▼
匯出 Excel（欄位與列序完全還原成原始格式）
```

## 3. 功能規格

### 3.1 班表匯入

- 支援點擊選檔或**拖曳檔案**到虛線區塊
- **標題列位置動態偵測**：掃描前 20 列，找到同時含「午別」「日期」「店號」的列即視為標題列，不假設固定列數
- **欄位動態辨識**：除已知欄位外，未預期的欄位一律原樣保留，匯出時不遺失
- 依「日期」分群，每個日期固定 30 列 ＝ 15 組 ×（午別 1 上午／午別 2 下午）
- 資料不足 30 列自動補空列，超過則截斷，並於 console 提出警告
- **組內配對規則**：依原始檔案位置成對切分（第 1、2 列為第 1 組…），組內再依「午別」欄位值決定上下午，**絕不重新排序**
- 純數字欄位自動補零：店號 6 碼、型態 4 碼、日期／前次盤點 8 碼、序 2 碼

已驗證：以實際班表（31 天、930 列、21 欄）測試匯入→匯出，除去除儲存格前後多餘空白外，逐格比對完全一致。

### 3.2 欄位歸屬（重要）

拖曳時哪些欄位跟著走，取決於此分類：

| 分類 | 欄位 | 行為 |
|---|---|---|
| **結構性** | 序、午別、日期 | 固定於槽位位置，不隨拖曳移動。序於匯出時依位置重新編號 |
| **人員** | 預定盤點者、備註、**人力**、**盤點1～8** | 隨人員卡片移動 |
| **門市** | 店號、店名、型態、前次盤點、課別、課別代號、營業課別，以及其他未預期欄位 | 隨門市卡片移動 |

**「人力」與「盤點1～8」屬於人員而非門市**，這點以 390 列實際資料驗證：

- 盤點N 的數量與「預定盤點者」字數，**0 筆不符**
- 「人力」欄位值與人數，**0 筆不符**
- 盤點N 的工號轉回代號後，與「預定盤點者」逐字對應

> ⚠️ 此分類曾經有誤（原本歸為門市），導致拖曳互換人員時工號留在原地、匯出後工號對錯人。v1.1.0 已修正。

### 3.3 人員代號 ↔ 工號對照表

班表每列的「預定盤點者」是代號串（如「董憶瑄」），「盤點1～8」依序是對應的工號，兩者一一對應。系統於匯入時掃描整份班表即可還原完整對照表，**不需依賴通訊錄 API**。

實作於 `src/utils/staffUtils.js` 的 `buildCodeToIdMap()`：

- 僅採用店號有填的列（避免備註列的雜訊文字混入）
- 代號數與工號數不符的列直接略過
- 同一代號若對應到多個工號，取出現次數最多者

實測結果：390 列建出 28 個代號、**零衝突**；以此對照表重算全部 390 列的工號與人力，結果與原檔**逐格完全一致**。

此對照表用於：使用者手動編輯「預定盤點者」後，自動重算「人力」與「盤點1～8」，避免工號與實際人員對不上。查無工號的代號會標紅提示，對應欄位留空而非寫入錯誤資料。

### 3.4 拖曳調移

| 拖曳來源 | 拖曳目標 | 行為 |
|---|---|---|
| 門市卡片 | 另一槽位的門市卡片 | 兩槽位的門市欄位互換 |
| 人員卡片 | 另一槽位的人員卡片 | 兩槽位的人員欄位互換（含人力與盤點1～8） |
| 店暫存區 | 槽位門市卡片 | 指派該店並從暫存區移除；**若原槽位已有門市，原門市退回暫存區原索引位置**，不覆蓋遺失 |
| 槽位門市卡片 | 店暫存區 | 門市退回暫存區，該槽位清空 |

門市與人員為獨立的拖曳型別，不會互相誤放。15 組 × 上下午的框架在任何操作下都不會被打亂。

### 3.5 店暫存區

側邊可收合面板。

**新增店**：店號（必填）、店名、型態、課別，以及**指定日期**。
指定日期後該店只能拖曳到該日期的槽位，拖到其他日期會被擋下並顯示提示。日期下拉選單來源為班表實際涵蓋的日期。

**匯入店庫異動**：
- 必填欄位：店號
- 選填欄位：店名、型態、日期、課別、其他任意欄位（原樣保留）
- 標題列自動偵測（找含「店號」的列），欄位順序不限
- 合併規則：以店號比對，既有則更新、新增則附加，暫存區其他項目不動

**日期欄正規化**（`normalizeDate()`）：

| 輸入 | 結果 |
|---|---|
| `20260803`、`2026/08/03`、`2026-8-3`、`2026年8月3日` | 直接辨識 |
| `8/3`、`8-3`、`8月3日` | 對照班表日期補年份 |
| 班表無該日 | 沿用同月份的年份，再退而求其次用第一個日期的年份 |
| 空白／無法辨識 | 不限日期 |

> 因省略年份的寫法需要班表日期當對照，建議**先匯入班表、再匯入店庫異動**。

**卡片標示**：
- 紫色 `限 MM/DD 週X`：已指定日期
- 橘色 `已排 MM/DD`：該店已排在班表其他位置
- 虛線＋半透明：指定日期非目前檢視的日期

### 3.6 當日出勤列

顯示該課別全體人員的單字代號，依當日被排班次數上色：

| 顏色 | 條件 | 意義 |
|---|---|---|
| 無色 | 0 次 | 今日未排班 |
| 淡藍 | 有休假且 0 次 | 正常休假 |
| 黃 | 1 次 | 帶 1 間店 |
| 綠 | 2 次 | 帶 2 間店（常態） |
| 紅 | ≥3 次，**或** 有休假卻仍被排班 | 需留意 |

> 紅色為提示而非錯誤。門市庫存較少時一人帶 3 間屬合理情況。

**計算規則（重要）**

- 僅統計**店號有填**的槽位。班表中店號空白的列常被用來記錄業務備註（如「效期 青+2PT」「秀皓 歐都納」），若一併統計會產生大量雜訊代號
- 「預定盤點者」欄位**逐字拆解**，每個字視為一位人員代號
- 課別範圍取自**整份班表**（掃描所有日期），而非當前日期。因週日等無排班日抓不到課別，會導致列出全部課別人員
- 代號在通訊錄中查無者（例如新人尚未建檔）仍照常顯示並計次，以虛線外框標示

滑鼠停留顯示：`劉育青（資深專員）・今日 2 次　休假中（特休）`

### 3.7 休假衝突警告

當某人當日有休假紀錄、且其代號出現在班表中，於班表上方顯示琥珀色橫幅，列出姓名、代號、假別、以及被排入的組別與時段。

需同時取得通訊錄（姓名↔代號對照）與休假資料才會啟用；任一缺少時橫幅不顯示。

### 3.8 門市重複偵測

業務規則：同一份班表中一間店原則上只盤點一次。系統以三層提醒：

1. **暫存區卡片**預先標示橘色 `已排 MM/DD`
2. **拖曳時**顯示訊息：`⚠ 門市重複：「005989 中賓店」已排定於 08/21 週五 第4組下午。`
3. **常駐橘色橫幅**列出整份班表所有重複門市，日期標籤可點擊跳轉

**僅警告不阻擋** — 轉換店等情況可能需要盤點第二次。

### 3.9 槽位編輯

點卡片上的鉛筆圖示開啟彈窗，可編輯店號、店名、型態、課別、前次盤點、預定盤點者、備註。

「預定盤點者」欄位下方即時顯示每個代號對應的工號；儲存時自動同步「人力」與「盤點1～8」。

### 3.10 日期切換器

- 橫向捲動，格式 `MM/DD 週X`（省略年份以保持精簡）
- **週日紅底、週六綠底、平日灰底**
- 選取中為紫底；若為週末則保留紅／綠外框以便辨識

### 3.11 班表匯出

依匯入時記錄的欄位順序與原始標題文字還原，每日 30 列。若原檔含「序」欄，匯出時依槽位位置重新編號為 01～30。

### 3.12 響應式版面

| 螢幕寬度 | 欄數 |
|---|---|
| < 640px | 1 |
| ≥ 640px | 2 |
| ≥ 1024px | 3 |
| ≥ 1280px | 4 |
| ≥ 1536px | 5 |

容器最大寬度 1800px。已於 1920、1366、1024、768 四種解析度驗證無橫向捲軸。

每組內部為**上下排列**：午別 1（上午）在上、午別 2（下午）在下。

## 5. 需 IT 協助的介接點

程式中所有待串接處皆以 `// TODO: IT 工程師請在此串接後端 API` 標註，集中於單一檔案：

**`src/services/staffApi.js`**

```js
export async function fetchRoster(departments) { ... }          // GET /staff/roster
export async function fetchLeave(departments, yearMonths) { ... } // GET /staff/leave
```

呼叫時機：`src/App.jsx` 的 `useEffect`，於班表匯入後、取得課別與年月時自動觸發。

### 通訊錄 API 提供的價值

由於工號對照已可由班表自行推導，通訊錄 API 主要用於：

1. **顯示姓名與職稱**（出勤列的滑鼠提示）
2. **列出今日未排班的人**（完整名單才知道誰沒被排到，即白色圓圈）
3. **關聯休假資料**（休假表以「姓名」為鍵，需靠通訊錄對應回代號）

### 需確認事項

1. **驗證方式**：目前為 `credentials: 'same-origin'`。若採 Token/SSO，請告知以便調整
2. **API 位址**：透過環境變數 `VITE_API_BASE_URL` 設定，預設 `/api`
3. **「班表代號」欄位**：需確認人事系統中確實有此欄位，且同一課別內唯一
4. **姓名一致性**：兩支 API 的「姓名」需完全一致，前端以此關聯休假與人員

## 7. 非功能性需求

- **無後端相依的降級行為**：API 無法連線時顯示提示，出勤列退回「僅統計班表內出現的代號」模式，班表匯入／拖曳／匯出完全不受影響
- **資料不落地**：所有 Excel 於瀏覽器記憶體處理，不上傳；人員資料僅存在於當次瀏覽階段，重新整理即清空
- **無寫入需求**：系統不回寫任何資料到後端

## 9. 目前限制

| 限制 | 說明 |
|---|---|
| 重新整理清空 | 所有資料在記憶體，重整需重新匯入（亦即個資不會留在瀏覽器） |
| 僅支援固定 30 列格式 | 「盤點行事曆報表」格式（午別為上／下、每日筆數 2～21 不等、無上下午配對）目前不支援，分組規則待業務端確認 |
| 型態補零 | 型態欄若原本為 `0`，因欄位標題標示「4碼」會補零成 `0000` |
